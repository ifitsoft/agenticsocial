# Phase 1.5 — Vertical Slice: `script.yaml` → MP4

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Render a hand-written three-beat `script.yaml` to a watchable ~10s vertical MP4, proving the whole pipeline connects.

**Architecture:** Python parses `script.yaml` + `series.toml` and emits `plan.json`. `render.mjs` reads that JSON, drives the existing engine through Playwright, and writes frames. Python calls ffmpeg. Node never sees YAML and gains no dependency.

**Spec:** `docs/superpowers/specs/2026-08-15-agenticsocial-video-mvp-design.md` §7, §9
**Roadmap:** `docs/superpowers/plans/2026-08-16-video-mvp-roadmap.md` §5 (Phase 1.5)
**Branch:** `feat/video-phase-1.5-vertical-slice`

## Global Constraints

- Python ≥3.11. **No new Python or Node dependencies.** `json` is stdlib; the engine already has Playwright.
- **`window.__seek(t)` stays pure** — no `Date.now()`, no randomness, no CSS keyframes. The determinism test ships green in the same commit as any engine change.
- One beat type only: `statement`. Vertical only (1080×1920). 30fps.
- The existing `scene.html?day=<date>` path must keep working unchanged — `content/2026-08-12.js` and `2026-08-14.js` still render.
- Everything under `workspace/` stays gitignored. Rendered output is not committed.

## What already exists (read before writing anything)

`engine/engine.js` provides, as globals on a classic script:

| | |
|---|---|
| `meta(m)` | sets episode metadata |
| `scene(act, dur, tag, build)` | pushes a scene; `build(s)` runs at init to create elements |
| `E(tag, cls, opts)` | create element; `opts` takes `{html, css, p}` |
| `P(text)` | → `{html: text}` |
| `rise(el, d0, o)` | masked word rise; `o` takes `{stag, dur}` |
| `init()` | publishes `window.__seek`, `window.__total`, `window.__scenes` |

`engine/scene.html` loads the day's script with `document.write('<script src="content/<day>.js">')`. **That mechanism is not incidental** — `fetch` and ES modules are both CORS-blocked over `file://`, which is why the plan arrives as a classic script rather than as JSON the page fetches.

`engine/render.mjs` takes `--day`, `--probe`, `--at`, `--pace`, launches Chromium at 1080×1920, and screenshots `window.__seek(i/30)` per frame.

## Tasks

**Task 1 — `plan.json` schema and emitter.** Pure Python, no engine, no subprocess. Parses the beats document (the first code in the project to do so), validates that every beat is a supported type, resolves `hold` durations and `pace`, folds in the series' design tokens, and writes `plan.json`. This is where Phase 4's format gets decided, so it carries the most design weight.

**Task 2 — engine reads a plan.** `planbuild.js`, the `?plan=1` branch in `scene.html`, `--plan` in `render.mjs`, and the determinism test. The existing `?day=` path must be untouched and still render both committed episodes.

**Task 3 — `agsoc video render`.** Wires plan → `node render.mjs` → ffmpeg → `out/vertical-1080x1920.mp4`. Owns the subprocess error surface: no ffmpeg, no node, a page error, a non-zero exit — each becomes a clean CLI error, never a traceback.

## Exit criteria

- [ ] A hand-written three-beat `script.yaml` renders to a playable MP4 the human can watch.
- [ ] `node render.mjs --day 2026-08-14` still renders the committed episode unchanged.
- [ ] The determinism test passes: the same `t` rendered twice is byte-identical.
- [ ] `agsoc video render` on a missing/invalid script fails cleanly, with no traceback.
- [ ] No new dependency in `pyproject.toml` or `engine/package.json`.
