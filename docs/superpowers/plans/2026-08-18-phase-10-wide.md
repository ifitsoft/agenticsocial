# Phase 10 — Wide format

**Goal:** The same approved script renders 1920×1080 as well as 1080×1920, and
neither format can silently lose content.

**Spec:** §9 (multi-format rendering) · **Roadmap:** §5
**Branch:** `feat/video-phase-10-wide` · **Depends on:** 8 — merged.

## The risk this phase actually carries

A layout change is the one kind of change that **passes every check this project
has built and still ships something wrong.** Verification compares text to
sources; drift compares authored inputs; determinism compares a frame to itself.
**None of them can see a beat whose text overflows its box at 1920×1080.**

So the exit criteria here are visual, and that is uncomfortable but honest: this
is the first phase where "the tests pass" is genuinely insufficient.

## What Phase 7 handed us, unresolved

**D-116:** `type_family` and `type_scale` are copied into `plan.json` and the
engine **ignores them** — leader-verified, neither string appears anywhere in
`engine/`. The type that is actually drawn lives in `scene.html`'s CSS, which no
approval covers.

Two knobs an operator would reasonably believe control the typography, that
control nothing. **This is the phase that touches layout, so this is where it is
resolved** — either wire them up or delete them, and say which.

## Global constraints

- **`window.__seek(t)` purity.** The determinism test ships green in the same
  commit as any engine change.
- **No pixel golden files** (Phase 4's ruling, unchanged): they are
  Chromium-version-bound and this project pins Playwright for exactly that
  reason. Assert on *page text and geometry*, not hashes.
- Python resolves timing; Node does zero arithmetic (D-007).
- **No test renders a full episode** — ~230 ms/frame.
- `probe` is how a human looks (D-119), and it must work per format.

## Tasks

**Task 1 — the format is a parameter, not a fork.** One layout system, two
viewports. A second copy of the beat builders is how the two formats drift apart
silently, and the second one is always the one nobody looks at.

**Task 2 — overflow must be loud.** A beat whose content does not fit its box is
**refused or visibly marked**, in both formats, at plan time if possible. Silent
clipping is the failure this phase exists to prevent, and it is invisible to
every existing check.

**Task 3 — `--format` end to end**, and `probe` per format. `approve` already
binds what the operator authored; **the format is chosen at render time and is
outside the approval** (D-116). Say so where an operator will read it.

## Open questions to decide, not default

- **Does one script legitimately produce both formats?** A 9:16 headline may
  simply not work at 16:9. If some beats need per-format text, that is a schema
  change and it is bigger than this phase — decide whether it is in or out, and
  do not discover the answer halfway through.
- **What is the safe-area rule at 16:9?** §2 gives 9:16 a safe area; the wide
  format needs its own, stated.
- **Does the approval need to cover the format?** Today it does not. Argue
  whether that is right, given the operator approves once and may render twice.

## Exit criteria

- [ ] The same approved episode renders both formats.
- [ ] A beat that overflows is refused or visibly marked, **in both formats**.
- [ ] `probe --format wide` produces frames a human can look at.
- [ ] Determinism green for both formats; no new pixel golden files.
- [ ] `type_family` / `type_scale` are wired up or deleted — decided, not left.
- [ ] The render output states that the format was **not** part of the approval.
